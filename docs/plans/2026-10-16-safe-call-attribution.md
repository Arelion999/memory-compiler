# Безопасная атрибуция вызовов — дизайн и план

Дата: 2026-10-16. Владелец делегировал выбор контракта («положусь на тебя»).

**Goal:** различать устройства и чаты, длительность и исход вызовов, причины гейта без PII в новой телеметрии.

**Architecture:** необязательный строковый _client_trace содержит компактный JSON версии 1: {"v":1,"device":"<UUID4 hex>","family":"codex|claude|kimi|kimiwork|unknown","call_id":"<UUID4 hex>"}. call_id необязателен для старых клиентов. Служебные поля удаляются до heal, dispatch и аудита аргументов и не восстанавливаются из текста. Сервер HMAC-SHA256 с разделением доменов device/chat; ключ MC_TRACE_KEY, иначе MC_API_KEY, иначе случайный ключ процесса. Смена ключа меняет псевдонимы. Это диагностические данные клиента, не аутентификация.

**Tech Stack:** Python stdlib, ContextVar, существующие MCP/Starlette, pytest.

## Альтернативы и выбор

Хеш hostname допускает словарный перебор и отвергнут. Только серверная атрибуция не различает устройства за общим мостом. Выбран случайный локальный токен, общий для адаптеров пользователя, в операционном ~/.cache/memory-compiler/trace.json; атомарное создание, fail-open при ошибке, без hostname/IP/путей в данных.

## Контракт

- Серверный trace отдельно от args: request_id, correlation_id, dur_ms, client_family, device_hash, chat_hash, chat_source, outcome, reason. Значения ограничены; ни свободных исключений, ни команд, ни аргументов. correlation_id копирует случайный call_id клиента и связывает локальный журнал с серверным; авторитетный request_id сервер генерирует сам. Локальные и серверные HMAC имеют разные домены.
- JSON ограничен 320 символами: точные ключи, v строго int 1, family по allowlist, device и call_id — lowercase UUID4 hex32. Повтор ключа, лишние поля, неверный тип и переполнение отбрасывают атрибуцию без отказа самого инструмента. Ошибки хранения токена дают unknown; UUID на каждый вызов для устройства не генерируется.
- Одно терминальное событие и одна запись аудита на вызов, включая раннюю валидацию, отказ проекта, исключения handler/postprocess. Существующие size/error/_count сохраняют смысл. ContextVar восстанавливаются в finally.
- Старые клиенты работают без метаданных. clientInfo нормализуется allowlist; неизвестное имя не пишется в новую телеметрию.
- session_hint принимает опциональный trace; auth/TTL/consume сохраняются. Конфликт одного fingerprint между разными чатами/устройствами не разрешается последней записью: unknown до истечения TTL. Старый hint_take остаётся совместимым.
- Канонизация fingerprint исключает _client_session и _client_trace на обеих сторонах; старые parity-векторы сохраняются.
- Хуки: gate.pass/card/valve/block сохраняют решения, добавляются enum причины и ранние gate.skip для memory_tool/loader/outside_scope. Новый trace и журнал не содержат сырой session, detail и произвольного tool_name. Для прочих старых событий detail не переносится в новые поля.
- session_arg.hint означает подтверждённое {"ok":true}; неудача отмечается фиксированным кодом, updatedInput сохраняется.
- Семейство Codex задаётся адаптером явно, отдельно от профиля core. Не угадывать по нормализованному событию. В репозитории — проверяемый helper/контракт подключения для vendored core; установленные файлы не менять.
- Порядок доставки после отдельного разрешения: сервер и поведенческая проверка, полный перезапуск клиента для новой схемы; затем выборочная доставка адаптеров с резервной копией и проверкой. Общий installer не обновляет Codex.
