# Очистка закрытых MCP-сессий: план исправления

> Выполнение: subagent-driven-development, TDD, затем независимое ревью.

**Цель:** явное завершение `/mcp` через DELETE освобождает запись транспорта и
владельца в менеджере; живые сессии, двухчасовой idle timeout и обработка старых
session id сохраняют поведение.

**Доказательство:** на установленном mcp==1.29.1 и текущей фабрике приложения
idle timeout 0.15 с уменьшает реестр 1→0. Три initialize→DELETE (HTTP 200)
оставляют 1→2→3 записи с `is_terminated=True`. SDK исключает такие транспорты
из очистки в finally; runner завершается, поэтому idle timeout больше их не удалит.

**Архитектура:** узкая очистка конкретного завершённого транспорта после обработки
запроса внутри существующего StaleTolerantSessionManager. Не фильтровать только
метрику: это скрыло бы удержание объектов. Не менять SDK/requirements: проект
фиксирует совместимую ветку 1.29.1. Не добавлять периодический sweep, если достаточно
очистки при завершении. Сверять объект перед удалением, если этого требует выбранный
способ получения транспорта; удалять связанную `_session_owners` запись.

## 1. Воспроизводящие поведенческие тесты

**Файлы:** новый `tests/test_mcp_session_cleanup.py`; использовать существующую
фабрику и реальный ASGI-обмен, аналогичный `tests/test_mcp_stale_session.py`.

1. initialize → DELETE → HTTP 200 и отсутствие закрытого id в реестрах.
2. Повторить цикл несколько раз: реестр возвращается к исходному размеру.
3. Две сессии: DELETE одной сохраняет вторую и её работоспособность.
4. Отказ DELETE из-за невалидной версии протокола не удаляет живую сессию.
5. Брошенная сессия реально истекает с коротким idle timeout; временное ускорение
   только на экземпляре менеджера в тесте, фабричный порог остаётся 7200 секунд.
6. Существующие сценарии старого id после рестарта остаются зелёными.

Сначала выполнить новый регрессионный тест на исходном коде и подтвердить
падение на оставшемся закрытом id, а не на ошибке тестового стенда.

## 2. Минимальное исправление

## Границы и критерии приёмки

Никакой работы с боевой базой и секретами в тестах, никаких изменений клиентских
конфигов или перезапуска контейнера. Активная основная копия и предыдущий архив
worktree не меняются. Успех — устранено удержание закрытых сессий, а не доказательство
того, что все исторические 2698 записей появились только по этой причине.
