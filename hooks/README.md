# hooks/ — сторож памяти memory-compiler для Claude Code и Kimi Code

`mc_guard.py` — единый хук-скрипт памяти для обоих клиентов: напоминает про
базу знаний (SessionStart, UserPromptSubmit), не пускает на живую
инфраструктуру без чтения базы (gate), следит, чтобы записи в базу не терялись
(очередь intent/fail/mark/stop + REST-досыл), доставляет рефлексы-памятки по
ошибкам и файлам (reflex/probe/nudge), блокирует редиректы в зарезервированные
имена Windows (nul_guard), напоминает про save_compact после сжатия контекста
(compact).

## Установка

```
python hooks/install.py                # оба клиента
python hooks/install.py --client kimi  # только Kimi Code
python hooks/install.py --dry-run      # показать изменения, ничего не писать
python hooks/install.py --force-env    # перезаписать существующий mc_guard.env
```

Инсталлятор копирует `mc_guard.py` в hooks-каталоги клиентов
(`~/.claude/hooks/`, `~/.kimi-code/hooks/`), перегенерирует секции хуков в
`~/.claude/settings.json` (ключ `hooks` целиком) и `~/.kimi-code/config.toml`
(только маркированный блок; чужие секции не трогаются), пишет `mc_guard.env`
рядом с каждой копией. Перед правкой конфига создаётся бэкап `*.bak-<дата-время>`.
Идемпотентно: повторный прогон без изменений источника ничего не пишет.

## Профили клиентов

Один скрипт обслуживает оба клиента. Профиль определяется по приоритету:
`--client=claude|kimi` в команде хука (его выписывает install.py в конфиг) →
переменная `MC_GUARD_CLIENT` → поле `client_type` события → эвристика по полям
события → fallback `claude` (с записью `client.fallback` в журнал хука).

От профиля зависят только: каталоги состояния (`~/.claude/hooks/` против
`~/.kimi-code/hooks/` — сознательно разнесены), форма информационных сообщений
(kimi — простой текст, claude — JSON) и способ блокировки Stop (kimi — причина
в stderr + exit 2, claude — JSON `{"decision": "block"}`).

## mc_guard.env

Машинно-специфичные значения лежат в `mc_guard.env` рядом с установленной
копией скрипта (в репо не коммитятся). Формат — `KEY=VALUE` по строкам, `#` —
комментарий. Разрешение каждой настройки: `os.environ` → `mc_guard.env` →
нейтральный дефолт.

| Переменная | Что задаёт | Дефолт |
|---|---|---|
| `MC_API_URL` | адрес REST сервера memory-compiler | `http://127.0.0.1:8765` |
| `MC_API_KEY` | ключ REST (досыл очереди, рефлексы) | пусто |
| `MC_KNOWLEDGE_DIR` | каталог базы (аудит-лог для свежести) | нет (свежесть отключена) |
| `MC_ENV_FILE` | дополнительный .env с MC_API_KEY | нет |

Без `MC_KNOWLEDGE_DIR` и без ключа скрипт работает, но деградирует: нет
предупреждений о чужих записях и автодосыла очереди.

## Тесты

Из каталога репозитория, два прогона (по одному на профиль):

```
MC_GUARD_CLIENT=claude python hooks/test_mc_guard.py
MC_GUARD_CLIENT=kimi python hooks/test_mc_guard.py
```

Сьюту не нужна сеть и база: REST заглушён, состояние пишется во временные
каталоги, боевые `~/.claude` / `~/.kimi-code` не трогаются.

## Публичность

Репозиторий публичный: в `hooks/` нет боевых адресов, путей и ключей — все они
живут только в локальном `mc_guard.env` на машине. Не вносите реальные значения
в исходники; при необходимости — плейсхолдеры вида `<NAS_IP>`.
