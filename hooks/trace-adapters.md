# Подключение атрибуции к клиентским адаптерам

Источник ядра — `hooks/mc_guard.py`. Этот документ описывает контракт для
последующей установки. Доставка и обновление установленных копий требуют
отдельного разрешения владельца и резервной копии адаптера, ядра и конфигурации.

## Контракт ядра

`trace_metadata(event=None, family=None)` возвращает JSON-строку `_client_trace`
или пустую строку при недоступности конфигурации. Поля: `v: 1`, `device`,
`family`, `call_id`. Device и call id — lowercase UUID4 hex32; family —
`codex`, `claude`, `kimi`, `kimiwork` или `unknown`. Каждый вызов helper создаёт
новый call id. Это диагностическая корреляция, не авторизация и не дедупликация.

`with_trace_arguments(args, event=None, family=None)` возвращает копию аргументов,
сохраняет `_client_session`, удаляет прежний `_client_trace` и добавляет новый при
успехе. При сбое метадаты аргументы вызова и session id сохраняются.

Все адаптеры на машине используют один `HOME/.cache/memory-compiler/trace.json`.
Он содержит `{ "v": 1, "device": "<UUID4 hex32>" }` и служит конфигурацией,
не хранилищем памяти. Создание — временный файл и атомарная hard link без замены
существующего файла. Если файловая система не поддерживает операцию, файл
недоступен или повреждён, атрибуция остаётся unknown. Автоматического исправления,
hostname/IP fallback и замены identity новым UUID при каждом вызове нет.

`TRACE_CLIENT_FAMILY` задаёт явное семейство атрибуции независимо от
`_CLIENT_CACHE`, управляющего прежним гейтом и форматом вывода. Kimi Work
опознаётся по документированному префиксу
`mcp__plugin-memory-compiler_memory-compiler__` до нормализации имени. Другие
события используют обычный детектор Claude/Kimi; fallback обозначается unknown.

Ограничение автоматического определения: текущий Kimi Work installer запускает
хуки с `--client=kimi`. Поэтому инфраструктурное событие может иметь family `kimi`,
а вызов памяти с plugin-префиксом — `kimiwork` в том же чате. Family — отдельная
диагностическая метка; локальный session HMAC зависит только от device и полного
chat id с постоянным доменом, поэтому такие события сохраняют общую группировку.
Для точного family на всех событиях адаптеру Kimi Work нужно явно задать
`TRACE_CLIENT_FAMILY = "kimiwork"` во всех путях. Этот документ не добавляет
installer-флаг и не меняет установленную конфигурацию.

## Codex: адаптер с отдельной копией ядра

Установленный `~/.codex/hooks/mc_codex.py` импортирует соседний
`mc_guard_core.py` как `G`, задаёт `G._CLIENT_CACHE = 'claude'` и сам добавляет
`_client_session`. Он не вызывает `cmd_session_arg`, поэтому замены одного ядра
недостаточно. Installer репозитория Codex не обслуживает.

После проверки совместимости ядра и отдельного разрешения на установку адаптер
должен явно задать `G.TRACE_CLIENT_FAMILY = 'codex'`, сохранив профиль гейта.
На каждом реальном исходящем вызове Memory Compiler необходимо ровно один раз
применить helper после существующего добавления session id:

```python
G.TRACE_CLIENT_FAMILY = "codex"
arguments = G.with_trace_arguments(arguments)
```

Покрыть все пути: PreToolUse `updatedInput`, bootstrap `route_project` и
`get_summary`, а также прямой `mcp_call` fallback, включая отдельные элементы
batch. Нельзя ставить helper одновременно на двух уровнях одного вызова:
это заменит call id. Повторная фактическая отправка получает новый call id.
Имена и поля события не используются для угадывания Codex.

Если адаптер ведёт локальный журнал этого вызова, передать ту же строку в
`G.journal(event, action, trace=arguments.get('_client_trace', ''))`. Тот же
payload используется для REST hint, если адаптер его отправляет. Успешным hint
считается только JSON object с `ok is True`; сбой не блокирует updatedInput.
Session id и trace исключены из fingerprint и сигнатуры повторов очереди.

Тест `tests/test_hook_trace.py` содержит fixture этих путей адаптера, проверяет
явное семейство, отдельные call id и неизменность gate profile. Он не является
доказательством доставки в установленный адаптер. После разрешённой установки
нужен отдельный поведенческий прогон каждого пути и проверка серверного аудита.

## Журнал

Новые записи содержат локальные HMAC-псевдонимы session/device, enum семейства,
фиксированные причины гейта и безопасную категорию инструмента. Свободное detail
не сохраняется. Локальные HMAC имеют отдельный домен: соединять с серверным
аудитом нужно через `correlation_id` session_arg событий. При unknown session
метрика учитывает блокировку, но не приписывает ей успешное чтение другого чата.
Существующие строки журнала и внутренние session id очереди не переписываются.
